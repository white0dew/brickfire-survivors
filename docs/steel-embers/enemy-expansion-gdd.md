# 《钢铁余烬 // STEEL EMBERS》
# 敌人与地图特色扩展策划案

> **版本**：v1.0 / 概念定稿
> **状态**：待实现
> **读者**：程序、关卡、美术、QA、后续接手的 AI Agent
> **目标**：把当前“5 普通 + 1 精英 + 1 Boss、12 张换色地图”的敌人结构，升级成可扩展的阵营/空域/行为系统；先做 15 个能打的单位，再扩到 40–60 个可战斗单位、100+ 图鉴变体。

---

## 0. 一页结论

### 0.1 问题

当前游戏的敌人数量，不是“图鉴少”，而是**真正不同的战斗行为太少**：

- 普通敌人 5 种：侦察履带、突击坦克、重装攻城车、自爆履带、磁轨猎手。
- 精英 1 种：精英·破城者。
- Boss 1 种：泰坦·攻城型。
- 图鉴 26 个条目中，有 19 个是**同一个 `elite` 模板换色、换名、加血**的封印守卫。
- 12 张地图共用一套全局 `WAVES`；地图只有布局、配色和 HP/速度/刷新倍率差异。
- 第 8 关和第 12 关使用完全相同的布局，只换了配色和难度。

### 0.2 方向

不是简单再加 20 个坦克皮肤，而是建立三层敌人体系：

| 层级 | 内容 | 作用 |
|---|---|---|
| **阵营** | 废铁军团 / 苍穹机群 / 异星舰队 / 封锁守卫 | 决定视觉、音效、移动方式、地图归属 |
| **空域** | 地面 / 空中 / 悬浮异星 / 固定炮台 | 决定是否受地形、水域、钢板影响 |
| **行为** | 突击、狙击、曲射、自爆、护盾、召唤、布雷、钻地、传送、光束 | 决定玩家怎么应对 |

**核心原则：一个敌人 = 一个清晰的威胁 + 一个清晰的解法。**

### 0.3 首轮目标

- 新增 **8 个地面单位、8 个空中单位、8 个异星单位**的设计池。
- 首轮只实现其中 **12 个新单位 + 3 个 Boss**，先跑通系统。
- 每张地图逐步拥有：**1 个专属机关 + 2–3 个标志性敌人 + 1 个 Boss/精英**。
- 图鉴从 26 条扩到 **100+ 条目**，但条目必须分组、可筛选，不能堆成无法阅读的列表。

## 1. 现状审计

| 项目 | 当前实现 | 结果 |
|---|---|---|
| 地图 | 12 张，30×18 tile，960×576 | 尺寸统一，适合快速做变体 |
| 基地/出生点 | 基地固定底部中央，玩家固定左下 | 每关开局路径一致 |
| 地图差异 | 布局、调色板、`mod` 数值倍率 | 缺少专属规则 |
| 波次 | 全局 6 段 `WAVES` | 所有地图共用敌人组合 |
| 普通敌人 | 5 个 AI 模板 | 基础职责齐全，但数量少 |
| 精英 | 1 个 `elite` 模板 | 19 个封印守卫只是换色 |
| Boss | 1 个泰坦 | 没有 Boss 类型差异 |
| 图鉴 | 26 条，普通/精英/Boss 分栏 | 条目数量与行为数量不匹配 |
| 地形 | 砖墙、钢板、水域、灌木 | 已有水域/穿墙 build 的雏形 |

### 1.1 可保留的优点

- 俯视视角、固定竞技场、6 分钟单局，非常适合做“敌人组合 puzzle”。
- 水域、钢板、灌木已经能支撑两栖、穿甲、卡位等 build 差异。
- 侧翼刷怪、基地防守、双人合作都可以直接复用。
- 现有封印守卫的 19 个名字/坦克对应关系，是现成的精英内容槽位。

### 1.2 必须避免的做法

- **不要**给 19 个守卫只加血量和颜色，然后宣称有 19 种精英。
- **不要**给每张地图只换一套调色板。
- **不要**一次写 100 个独立 AI 脚本；用行为模块组合。
- **不要**让空中单位完全替代地面单位；空中应是压力层，不是唯一答案。

## 2. 设计目标与衡量标准

### 2.1 玩家体验目标

1. **第一眼能认出威胁**：看轮廓、颜色、影子，就知道是冲锋、炮击、护盾还是空中单位。
2. **每 30 秒出现一个新决策**：新敌人、地图机关、精英或 Boss 改变站位/武器选择。
3. **每张地图有一个记忆点**：玩家能用一句话描述，例如“熔炉会喷火”“沼泽水会导电”“反应堆要躲辐射区”。
4. **每个阵营有不同节奏**：废铁军团压地面，苍穹机群逼走位，异星舰队破坏规则。
5. **失败可归因**：被盾墙车挡住、被炮击预判、被空中单位绕后，而不是“莫名其妙掉血”。

### 2.2 内容指标

| 指标 | 首轮（MVP） | 完整版目标 |
|---|---:|---:|
| 新可战斗单位 | 12 | 40–60 |
| Boss 模板 | 3 | 6 |
| 有专属机关的地图 | 3 | 12 |
| 有专属敌人池的地图 | 6 | 12 |
| 图鉴条目 | 40+ | 100+ |
| 每关同时出现的不同敌人类型 | ≤ 6 | ≤ 8 |

> 数量不是越高越好。屏幕上同时超过 8 种敌人时，玩家会失去阅读能力；更多内容应该通过**地图轮换、阵营组合、精英变体**出现，而不是一屏全塞。

## 3. 核心系统：敌人 = 阵营 × 空域 × 行为 × 角色

### 3.1 空域（Domain）

| Domain | 移动规则 | 视觉规则 | 玩法作用 |
|---|---|---|---|
| `ground` | 受砖墙/钢板/水域阻挡；两栖单位可过水 | 履带、车轮、低矮轮廓 | 当前主力；利用地形 |
| `air` | 忽略地面 tile；不可被地面近战碰到 | 机翼/旋翼、地面阴影、悬浮高度 | 逼玩家离开掩体、分散火力 |
| `hover` | 可过水域，不可穿钢板；部分可传送 | 无轮、悬浮环、能量尾迹 | 异星单位；破坏地形安全感 |
| `static` | 不移动 | 炮塔/方尖碑/核心 | 阵地压力；必须绕后或拆掉 |

### 3.2 行为原型（Behavior）

| 行为 | 描述 | 玩家解法 |
|---|---|---|
| `rusher` | 直线逼近，接触伤害/冲锋 | 侧移、减速、近身爆发 |
| `ranged` | 保持距离，直接射击 | 掩体、突进、优先击杀 |
| `artillery` | 预判位置，抛射范围伤害 | 离开预警圈、不要站桩 |
| `bomber` | 贴近后自爆/投弹 | 远程击毁、保持距离 |
| `support` | 护盾、修复、标记、加速 | 优先点杀 |
| `summoner` | 召唤小怪/无人机 | 打母体、清小怪、AOE |
| `trapper` | 地雷、蛛网、毒池 | 清场、绕路、远程拆 |
| `ambusher` | 钻地、传送、伏击 | 观察预警、保持移动 |
| `boss` | 多阶段、多招式 | 记招式、利用场地 |

### 3.3 数据字段建议

```js
{
  id: 'bulwark',
  name: '盾墙车',
  en: 'BULWARK',
  faction: 'rust',
  domain: 'ground',
  role: 'tank',
  tier: 2,

  hp: 420, speed: 22, radius: 18,
  damage: 16, xp: 24,

  ai: 'bulwark',                 // 行为模块 ID
  weapon: { type: 'none' },
  mods: ['frontShield'],         // 护盾/分裂/修复等
  spawn: {
    maps: [1, 3, 5, 8],
    waves: [1, 2, 3],
    weight: 6,
    cap: 2
  },
  visual: {
    body: '#a85a32', light: '#ffb87a', dark: '#3a1c12',
    core: '#ffb52d', scale: 1.25, shadow: true
  },
  codex: {
    role: '正面减伤，必须绕后',
    counter: '侧翼、电弧、范围伤害',
    maps: '熔炉工厂 / 霜蚀边陲 / 余烬高架 / 终焉穹顶'
  }
}
```

> 现有 `ENEMIES` 可以继续保留为“配置表”，但 AI 更新逻辑必须按 `ai`/`domain` 分发，不能继续在一个函数里堆 `if (type === ...)`。

## 4. 阵营设定

## 4.1 废铁军团 // RUST LEGION

**关键词**：柴油、焊死钢板、橙色残漆、履带、黑烟、正面推进。
**叙事**：旧战争留下的自动化装甲集群，占领熔炉、港口和高架，靠数量和装甲碾过防线。
**玩法**：地面压力、正面盾、曲射、布雷、维修，逼玩家绕后和换弹种。

| ID | 名称 | 角色 | 核心行为 | 反制 |
|---|---|---|---|---|
| `bulwark` | 盾墙车 | 坦克 | 正面 65% 减伤，缓慢推进 | 绕后、电弧、曲射、穿甲 |
| `mortar` | 炉膛迫击车 | 曲射 | 预判玩家位置，1.0s 后落炮 | 离开红圈、突进 |
| `minelayer` | 布雷履带 | 区域封锁 | 沿途丢 3 枚感应雷 | 远程打雷、绕开 |
| `splitter` | 分裂运输车 | 召唤 | 死亡分裂成 3 只小型履带 | 远程击杀、AOE |
| `borer` | 钻地车 | 伏击 | 钻地 1.2s，从玩家附近冒出 | 观察尘土预警、保持移动 |
| `welder` | 维修车 | 支援 | 光束修复最近机械单位 4%/s | 优先集火 |
| `charger` | 破阵冲锋车 | 突击 | 0.7s 蓄力后直线冲锋 | 侧移、减速、地形阻挡 |
| `spotter` | 雷达车 | 支援 | 标记玩家，周围敌人加速/加射速 4s | 优先击杀 |

**视觉语言**：宽履带、低车体、焊接钢板、橙色残漆；支援单位有绿色/青色维修光束。

## 4.2 苍穹机群 // SKY SWARM

**关键词**：无人机、探照灯、铜色装甲、青色尾焰、空中阴影。
**叙事**：封锁区上空的自动防御网，原本用于拦截飞行器，现在把一切地面移动都当作目标。
**玩法**：无视地面障碍、从边缘切入、俯冲/轰炸/空投；逼玩家离开掩体、分配对空火力。

| ID | 名称 | 角色 | 核心行为 | 反制 |
|---|---|---|---|---|
| `drone` | 侦察无人机 | 突击 | 绕玩家盘旋，三连点射 | 快速点杀、范围武器 |
| `strafer` | 俯冲翼 | 直线 | 先画出一条红色扫射线，再俯冲扫射 | 离开红线、掩体 |
| `bomber` | 轰炸机 | 曲射 | 横穿战场，沿路径丢 3 枚炸弹 | 提前移动、打爆炸弹 |
| `gunship` | 炮艇 | 坦克 | 悬停边缘，持续火力压制 | 掩体、对空爆发、逼它换位 |
| `carrier` | 无人机母舰 | 召唤 | 每 6s 释放 1 架无人机，最多 4 架 | 优先打母舰、AOE 清小机 |
| `transport` | 空投运输机 | 支援 | 飞越后空投 4 个地面单位 | 空投前击杀、落点 AOE |
| `interceptor` | 截击机 | 伏击 | 俯冲穿过玩家，再拉升脱离 | 侧移、预判回旋 |
| `shielddrone` | 护盾无人机 | 支援 | 给 3 个地面单位套 30% 护盾 | 优先点杀、EMP/电弧 |

**视觉语言**：不画履带；机翼/旋翼轮廓；地面必须有阴影，阴影位置提示真实碰撞点。
**限制**：空中单位同时存在不超过场上敌人的 35%；避免地图地形完全失效。

## 4.3 异星舰队 // XENO FLEET

**关键词**：黑紫装甲、青色能量、悬浮环、无轮、生物机械、空间扭曲。
**叙事**：封印核心并非人类造物；深层星区的“守卫”只是外壳，真正的异星舰队在核心破裂后开始苏醒。
**玩法**：悬浮、传送、护盾、光束、引力、虫巢；破坏玩家对地形和距离的安全感。

| ID | 名称 | 角色 | 核心行为 | 反制 |
|---|---|---|---|---|
| `saucer` | 侦察飞碟 | 直线 | 悬浮横移，持续光束点射 | 横向拉扯、掩体 |
| `beamfrigate` | 光束护卫舰 | 曲射/直线 | 1.1s 蓄能，释放贯穿光束 | 离开光束线、绕侧 |
| `warper` | 跃迁者 | 伏击 | 每 4s 传送到玩家侧后方 | 观察空间扭曲、近身爆发 |
| `warden` | 异星守卫 | 支援 | 给周围敌人 40% 减伤护盾 | 先破盾、集火 |
| `hive` | 虫巢母舰 | 召唤 | 持续孵化异星爬虫 | AOE、优先母体 |
| `gravit` | 引力舰 | 控制 | 2s 内把玩家向它拉近 | 反向移动、冲刺、击毁 |
| `weaver` | 织网者 | 区域封锁 | 在地面铺减速/伤害网 | 烧网、绕行、远程拆 |
| `obelisk` | 方尖碑 | 固定炮台 | 旋转光束扫射，不可移动 | 找掩体、绕后、穿甲 |

**视觉语言**：无履带、无炮管；悬浮环/能量核心；青色和紫色发光；攻击前有明显的能量聚集。

## 4.4 封锁守卫 // SEAL GUARDS

现有 19 个封印守卫保留名字、配色、对应坦克和关卡，但每个守卫必须获得**一个真正的行为修饰**，不能只加血量。

| 对应坦克 | 守卫特性 | 行为 |
|---|---|---|
| 双管 M-02 | 双联弹幕 | 每次射击 2 发，扇形扩散 |
| 铁壁 M-03 | 正面盾 | 正面 60% 减伤，转身慢 |
| 疾风 M-04 | 冲刺 | 蓄力后突进 |
| 磁轨 M-05 | 穿透光束 | 直线穿透，需离开射线 |
| 焚化 M-06 | 火焰轨迹 | 移动留下短时火墙 |
| 雷暴 M-07 | 连锁闪电 | 命中后弹射 2 个目标 |
| 蜂巢 M-08 | 释放无人机 | 每 8s 放 2 架小无人机 |
| 工兵 M-09 | 部署炮塔 | 放置一座短命哨戒炮 |
| 天罚 M-10 | 预判炮击 | 连续 3 个落点预警 |
| 霜牙 M-11 | 减速场 | 周围地面结霜，降低移速 |
| 磁力 M-12 | 引力 | 把玩家向自己拉 |
| 拾荒 M-13 | 拾取强化 | 吃掉场上掉落物，回血/加速 |
| 吸血鬼 M-14 | 吸血 | 伤害玩家时回复自身 |
| 玻璃炮 M-15 | 高伤低血 | 伤害极高，但生命低 |
| 医疗 M-16 | 修复友军 | 治疗周围单位 |
| 巨兽 M-17 | 冲撞护甲 | 高护甲，冲撞时免疫击退 |
| 幽灵 M-18 | 相位 | 周期性半透明，减免弹道伤害 |
| 爆破 M-19 | 死亡爆炸 | 死亡时留下大范围爆炸 |
| 毒蝎 M-20 | 毒池 | 攻击留下持续伤害区域 |

**实现优先级**：先做 6 个通用特性（盾、冲刺、曲射、召唤、减速、死亡爆炸），套到 19 个守卫上；其余特性在第二阶段补齐。

## 8. 地图机关系统

### 8.1 数据建议

```js
{
  id: 'furnaceVent',
  name: '熔炉喷口',
  type: 'zone',
  period: 8.0,
  warning: 1.2,
  active: 2.0,
  damage: 8,          // 每 0.5s
  radius: 48,
  affects: ['player', 'ground', 'air'],
  telegraph: 'ring',
  safe: 'leaveRadius'
}
```

### 8.2 机关规则

- 每个机关必须有 **预警 → 生效 → 消退** 三段，不能无提示伤害。
- 机关可以伤害敌人，给玩家“引怪进机关”的操作空间；Boss 除外。
- 机关不能完全封死基地；基地受到机关伤害降低 50%。
- `amphibious` 对水域机关：免疫减速，但不免疫电击/毒伤。
- `phase` 不免疫机关；相位只处理钢板/弹道，不应让地图机制失效。
- 空中单位不受地面机关影响，但会被“防空/风暴/激光”类机关影响。
- 每张地图只做一个主机关；最终关可以叠加第二个轻量机关。

### 8.3 12 个机关原型

| 机关 | 地图 | 预警 | 效果 | 解法 |

## 9. 波次与生成系统

### 9.1 从全局波次改为“地图池 + 波次模板”

当前所有地图共用 `WAVES`。建议保留 6 分钟节奏，但每张地图通过 `enemyPool` 选择敌人：

```js
MAPS[0].enemyPool = {
  rust: 0.8,
  sky: 0.2,
  xeno: 0,
  signature: ['bulwark', 'mortar', 'welder']
};
```

生成器规则：

1. 从地图的 `enemyPool` 抽阵营，再从阵营中抽单位。
2. 每波至少保证一个“角色配额”：1 个远程/曲射 + 1 个近战/突击；避免全是同一种。
3. 第一次出现的新单位给 **1.5s  Spotlight**（名字 + 威胁提示），并写入图鉴。
4. 同屏不同单位类型上限 6–8；空中不超过 35%；支援不超过 2。
5. 封印守卫按现有 `SEAL_TANKS_BY_STAGE` 触发，不参与普通池。

### 9.2 6 分钟节奏

| 时间 | 阶段 | 内容 |
|---|---|---|
| 0:00–1:00 | 接触 | 地面 T1；教学式引入 1 个新单位 |
| 1:00–2:00 | 加压 | T1 + T2；第一次精英 |
| 2:00–3:00 | 空域 | 空中单位登场；地图机关第一次完整周期 |
| 3:00–4:00 | 异星 | 异星单位/护盾/传送；混合波 |
| 4:00–5:00 | 高潮 | 精英 + 小 Boss；机关频率提高 |
| 5:00–6:00 | Boss | 地图 Boss/最终 Boss；机关进入最终模式 |

> 首轮 MVP 可以只做 3 张地图的完整节奏，其他地图先用“同阵营不同配比”过渡。

## 10. 数值、可读性与平衡

### 10.1 数值区间

| Tier | HP | 速度 | 伤害 | XP | 半径 |
|---|---:|---:|---:|---:|---:|
| T1 | 40–160 | 34–70 | 5–18 | 2–8 | 9–14 |
| T2 | 220–450 | 22–52 | 12–28 | 18–40 | 13–20 |
| T3 | 750–1200 | 18–32 | 20–40 | 50–100 | 18–30 |
| Boss | 8k–25k | 12–30 | 20–45 | 250–500 | 26–44 |

- 空中：HP ×0.7，速度 ×1.2，半径 ×0.8；同屏上限 35%。
- 支援：HP ×0.8，不直接输出，必须容易被识别。
- 护盾/减伤：不要超过 70%，且给出绕后/破盾窗口。
- 难度：沿用现有 `difficultyMod`，但新单位不要只靠 HP 倍率变强；优先增加行为组合。

### 10.2 可读性规则

- **轮廓优先**：地面有履带，空中有机翼/旋翼和阴影，异星无轮悬浮。
- **颜色语义**：废铁橙红、苍穹铜青、异星紫青、支援绿色/青色光束、Boss 红白。
- **预警统一**：红圈 = 立即离开；黄线 = 即将扫射；绿光 = 支援/护盾；紫光 = 传送/异星。
- **音效区分**：炮击、轰炸、传送、护盾至少各有一个独立提示音。
- **屏幕上限**：同屏小怪不超过 45；同屏精英不超过 3；Boss 战小怪不超过 12。

### 10.3 反制矩阵

| 威胁 | 主要解法 | 次要解法 |
|---|---|---|
| 盾墙车 | 绕后/电弧 | 穿甲、曲射 |
| 炮击/轰炸 | 离开预警圈 | 冲刺、掩体 |
| 空中单位 | 对空爆发/分散 | 掩体、诱导俯冲 |
| 护盾/维修 | 集火支援单位 | EMP、范围伤害 |
| 传送/钻地 | 保持移动、观察预警 | 近身爆发、陷阱 |
| 虫巢/母舰 | AOE 清小怪 + 打母体 | 穿透、狙击 |
| 机关 | 记周期、找安全区 | 两栖/相位/冲刺 |

## 12. AI 美术管线

### 12.1 概念阶段

使用 `gpt-image-2.5` 生成 16:9 概念板，风格参考现有：

- `assets/ai/vanguard-portrait.png`
- `assets/ai/vanguard-keyart.webp`

**概念板要求**：

- 3/4 概念插画只用于定轮廓、材质和配色；**不是最终资产，不做三视图，不做 3D 模型**。
- 最终战斗资产必须是**顶视 2D 像素 sprite**，不能把 3/4 插画直接缩小当 sprite。
- 高细节像素插画/游戏概念图混合；粗轮廓、清楚剪影。
- 深炭黑背景，橙色/青色主光源。
- 每个单位独立、等距排列，不重叠。
- 图中不要生成文字、UI、logo；名称由后期排版加。

### 12.1.1 本项目真正的 sprite 形态

不是三视图，而是：

| 文件 | 内容 | 用法 |
|---|---|---|
| `body.png` | 1 帧顶视车身，车头朝上 | Canvas 按移动方向旋转 |
| `turret.png` | 1 帧顶视炮塔，炮口朝上 | Canvas 按瞄准方向独立旋转 |
| `shadow.png` | 空中单位的椭圆阴影 | 不参与碰撞，只做高度提示 |
| `glow.png` | 异星能量核心/悬浮环 | 叠加发光，可单独闪烁 |
| `body_02.png` | 可选的 2 帧履带/旋翼动画 | 不做整套 4/8 方向帧 |

> 像素游戏不需要三视图。车身和炮塔都只画**正上方俯视**的一帧，靠 Canvas 旋转复用；只有轮廓特别不对称、旋转后穿帮时，才追加 4/8 方向帧，而不是默认全套。

### 12.2 战斗内精灵阶段

- **地面单位**：32×32 或 48×48 顶视像素车身；重型 64×64；车身与炮塔分离，Canvas 分别旋转。
- **空中单位**：32×32 或 48×48 顶视机体 + 独立阴影层；阴影不参与碰撞。
- **异星单位**：48×48 或 64×64，悬浮环/能量核心可单独发光。
- **Boss**：96×96 或 128×128；可先用代码形状做原型，再替换为大体量 sprite。
- 所有 sprite：透明底、固定中心锚点、统一比例、1px 深色描边、16–24 色、最近邻缩放、不做抗锯齿。
- 运行时纹理总预算：首屏 < 2MB，完整包 < 6MB；优先 WebP + atlas。

### 12.3 资产命名

```text
assets/enemies/rust/bulwark/body.png
assets/enemies/rust/bulwark/turret.png
assets/enemies/sky/drone/body.png
assets/enemies/sky/drone/shadow.png
assets/enemies/xeno/saucer/body.png
assets/enemies/bosses/skycarrier/phase-1.png
```

### 12.4 实现顺序

1. 代码形状/色块原型，先把行为跑通。
2. AI 概念板确认轮廓和配色（概念方向稿）。
3. 按顶视像素规范重绘 `body + turret`，不要从三视图/3D 模型导出。
4. 单位立绘/图鉴头像。
5. 战斗 sprite 逐批替换；没有通过 24/48/72px 可读性测试的资产不允许进游戏。

## 13. 实施阶段与验收

- 确认 3 个阵营、12 个 MVP 单位、3 个 Boss、3 张试点地图。

范围：

- 3 张地图：01 熔炉工厂、02 霓虹沼泽、07 零号反应堆。

- 3 张地图的机关均有预警、周期、安全区。

### Phase 3：数量与美术

- 100+ 图鉴条目（含精英/地区变体）。
- AI 概念图/头像/立绘批量生产。
- 战斗 sprite 替换、音效、特效、平衡。
- 性能与移动端适配。

### 优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | domain/ai 框架、地图 enemyPool、3 个机关、12 个 MVP 单位 | 没有框架，后面全是堆脚本 |
| P0 | 图鉴筛选、首次遭遇 | 玩家要能感知新内容 |

| P1 | 空中/异星完整阵营、地图卡片 | 地图特色核心 |
| P2 | 100+ 变体、AI 战斗 sprite、额外皮肤 | 数量与包装 |

## 14. 风险与非目标

### 风险

| 风险 | 处理 |
|---|---|
| 屏幕太乱 | 同屏类型上限、轮廓语言、颜色语义 |
| 空中单位让地形失效 | 空中占比 ≤35%；地面仍是主体 |
| 100 个图鉴没人看 | 分组、筛选、地图关联、首次遭遇 |
| AI 图风格漂移 | 统一参考图、调色板、轮廓规范、人工筛选 |
| 数值膨胀 | 先做行为差异，再做倍率；按 Tier 预算 |
| 新单位卡地形 | 统一寻路/碰撞测试；每个 domain 单独测试 |

### 非目标

- 不做 3D、不做自由地图、不做联网。
- 不在首轮做 100 个独立 AI；先做 12 个可战斗单位。
- 不把现有代码画的坦克全部替换成 AI 图；先做概念/图鉴/菜单，再评估战斗 sprite。
- 不让 AI 生成 UI 文本或游戏内文字。
